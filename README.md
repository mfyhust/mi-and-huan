# 觅&还 · 校园失物找回智能体

面向中文校园场景的持续寻物助手。用户可以描述“可能在五餐二楼丢了一只黑色杯子”，逐轮补充、更正条件；智能体查询实际登记记录，解释候选差异，记住排除反馈，并在新线索出现后继续跟进。

作者：梅飞宇。当前版本：`1.2.0-rc.2`。本项目使用 AI 辅助开发。

## 能做什么

- **多轮寻物**：保留确定、可能、记不清和明确排除的条件，支持楼层、日期范围、主体与部件颜色，以及后续更正。
- **可解释候选**：区分吻合、冲突和待核实特征，按候选差异提出问题；不会把排序分数当作归属概率。
- **持续跟进**：排除与恢复候选、订阅后到线索、站内提醒，以及持久化任务恢复。
- **校园地点**：内置211条上海交通大学闵行校区公开地点事实，保留来源；用户提供的新名称、别名须确认后才记住。拾获地点与保管去向分开。
- **图片辅助**：从图片提取外观草稿，用户核对后发布；图片处理与跨账号访问控制。当前不是以图搜同一物品系统。
- **协作找回**：拾获登记、认领说明、保管人核实、交接口令和双方确认。模型不能裁定所有权。

任务记忆、工具、执行控制、匹配、反馈和跟进由本项目实现；基础模型用于推理，没有接入第三方成品 Agent 替代业务核心。具体来源见 [第三方说明](THIRD_PARTY_NOTICES.md)。

## 两个版本

| | API版 | 本地模型版 |
|---|---|---|
| Agent核心 | 共用 `lib/` | 共用 `lib/` |
| 模型 | 用户配置的基础模型API | 本机Ollama开源模型 |
| 模型网络 | 需要可用API和网络 | 固定 `127.0.0.1:11434`，服务端拒绝外部模型与云端覆盖 |
| 业务数据 | `.api-data/` | `.offline-data/` |
| 默认网页 | `http://127.0.0.1:5173` | `http://127.0.0.1:5174` |

两版独立配置、启动和保存数据，不自动同步。模型不可用时会明确显示规则辅助；离线版不会自动改用外网API。**源码仓库不含模型权重、运行器、密钥或业务数据库**。准备依赖和模型可能需要联网，准备完成后的断网运行是另一项验证。

## 从源码运行

已验证环境为 Ubuntu 22.04 / Linux x86_64、Node.js v24.22.1。工程最低Node版本为22.13；其他系统尚未完成同等验收。GPU和内存需求取决于基础模型，不能保证所有电脑有相同速度。

先克隆本仓库并进入根目录，安装锁定依赖：

```bash
node --version
npm ci
npm run verify
```

### API版

```bash
npm run build:api-static
npm run start:api
```

打开 `http://127.0.0.1:5173`，在模型设置中配置自己的服务、模型和密钥。也可以把 `api/config.example.json` 复制为 `api/config.local.json` 后填写；该私密文件已被Git忽略。示例里的交大模型名称是2026-10-25的已测配置，不保证其他账号权限或服务端目录不变。

文本模型和图片识别模型分别配置；文本模型可用不等于支持图片。并发或限流时会提示等待，没有自动重试、排队或供应商切换。

### 本地模型版

先自行准备受支持的Ollama和 `qwen3.5:4b-q4_K_M` 模型及视觉投影权重。仓库中的准备脚本默认只显示计划：

```bash
python3 scripts/prepare-local-model.py
```

如明确需要下载固定版本，可在核对磁盘空间、来源和许可后运行 `python3 scripts/prepare-local-model.py --download`。该步骤会下载较大的第三方文件，不是启动要求的自动操作。也可迁入已经准备好的 `.offline-runtime/` 和 `.offline-models/`，保留目录结构与原许可。

准备完成后，先构建网页：

```bash
npm run build:offline
```

在第一个终端启动本机模型服务：

```bash
node offline/start-model.mjs
```

在第二个终端启动应用：

```bash
npm run start:offline
```

打开 `http://127.0.0.1:5174`。启动脚本只启动已准备好的服务，不自动下载模型。使用其他模型前要核对工具调用、图片协议和配置限制，不能只更改名称就声称兼容。

## 五分钟功能体验

1. 在合成演示工作区登记一只黑色杯子，拾获地点填写“第五食堂二楼”，另填保管去向。
2. 切换演示身份，描述“五餐附近丢了杯子，可能是黑色的”。查看实际候选、吻合依据和待核实项。
3. 补充“二楼，杯盖可能是银色的”，再说“杯盖颜色记不清”，核对条件变化与记忆。
4. 排除一条候选，再恢复；没有合适线索时选择持续留意，登记新线索后检查站内提醒。
5. 提交认领说明，由保管人核实后进行交接。只用合成特征，不填写真实证件或他人私密信息。

合成演示身份不等同真实账号。需要多人协作时，使用账号模式，见 [使用指南](docs/使用指南.md)。

## 测试与限制

2026-10-25参赛冻结版本通过204项回归测试和类型检查；真实DeepSeek完整合成场景3/3通过；Linux实际交付包在无外网网络环境完成23次本机模型请求及核心流程。它们分别是软件回归、有限模型场景和交付运行验证，**不是校园真实找回率，也不是照片识别准确率**。开源快照的独立构建与回归检查另见 [导出核验](docs/开源核验.md)。

个人照片集未验证；公开照片集规模很小，预标注未作独立人工金标准。没有校方数据库、监控、微信消息、GPS或官方合作接入；地点名称不代表实时GIS或完整室内布局。站内提醒不等于离线推送到手机。当前网页没有部署历史LoRA实验适配器。

这里采用两个独立静态应用入口；旧Sites/Worker模板入口保留兼容源码，本次未验证其外部托管。

常规 `npm run verify` 不调用真实模型或付费API。真实评测脚本默认显示计划，显式 `--run` 才推理；只使用合成业务资料或已说明来源的图片。独立断网验证还需要操作系统网络隔离，不能用模型模拟测试代替。参见 [验证说明](docs/验证说明.md)。
