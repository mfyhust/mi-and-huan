# Windows 11 独立运行与交接测试

适用：Windows 11 x64，从GitHub下载源码ZIP后解压。不依赖原Linux电脑持续开机，不依赖ChatGPT或Codex账号登录。另一个GPT账号仅协助测试与修改代码，不是本应用的基础模型配置。

## 先准备与启动

1. 从官方 https://nodejs.org/ 安装Windows x64的Node.js 24 LTS完整版（含npm）。本项目需要Node内置SQLite，不适用旧Node18/20。关闭旧终端再打开。
2. GitHub登录有仓库权限的账号，进入仓库，选择Code → Download ZIP。解压到例如`D:\mi-and-huan`，不要直接在压缩包里运行；不要复制Linux的node_modules或Linux Node运行器。
3. 双击`Windows首次准备.cmd`，它执行锁定依赖安装、构建两版页面及环境检查。首次需要网络安装通用工程依赖，不下载模型、不调用模型。失败时保留错误信息，不能把窗口出现当成安装成功。
4. 双击`启动API版-Windows.cmd`，保持窗口开启，用浏览器打开 http://127.0.0.1:5173/ 。API配置还没准备时可检查规则流程，但不能据此声称API模型调用成功。
5. API真实调用需由本人在本机复制`api/config.example.json`为`api/config.local.json`并配置有效的基础模型密钥。文件在Git忽略范围内；不发给GPT，不截图密钥，不提交远端。默认供应商与字段约束见示例。修改后重启API服务。
6. 双击`启动本地版-Windows.cmd`，用浏览器打开 http://127.0.0.1:5174/ 。这是独立本地数据，不会自动同步Linux现有账号、照片或留言。

以上是源码启动支持。GitHub源码不含构建产物、Node、模型权重、Ollama或真实私密配置；不是下载ZIP后无需准备的免安装程序。

## 本地模型单独准备

Windows需要Windows版Ollama，官方安装说明 https://docs.ollama.com/windows 。不要执行Linux可执行文件；不需要安装WSL来启动本项目。

- 使用原有模型配套时，将`.offline-models`目录（内含`blobs`和`manifests`）复制到项目根目录，权重可沿用，不必重新训练。原模型TAR包含Linux运行器，Windows忽略该运行器，只使用模型文件。
- 从系统托盘退出其他正在运行的Ollama实例，避免它占用11434端口或使用不同模型目录；不要强制结束不明进程。
- 双击`启动本机模型-Windows.cmd`，它会寻找项目内`.offline-runtime/ollama-windows-amd64/ollama.exe`、官方默认安装目录或PATH中的`ollama.exe`，固定本机监听及项目模型目录、关闭云功能，不自动下载权重。
- 模型服务和本地版窗口都保持开启。未检测到模型时的规则降级不代表真实模型验证通过。
- Windows内存、显卡与速度尚需在目标电脑实测。先双击`检查Windows环境.cmd`收集平台、内存、SQLite及照片处理结果；此检查不做模型推理，也不证明已断网验收。

## 给另一个GPT的测试任务

请先阅读根目录AGENTS.md、README.md和本文，再做本机测试。目标是验证Windows独立启动，不改Agent架构、不改模型目的地限制、不重新训练或重做界面。

允许：读取非私密源码，检查Node/npm版本，运行`npm.cmd ci`、`npm.cmd run verify`、两版静态构建及`node scripts/check-desktop.mjs`，使用明显标记的合成数据测试。修复需小范围、逐项记录、保留原有依赖锁和功能边界。

不得：读取/输出/上传真实模型配置、密码、Cookie和用户照片；提交业务数据库、下载大模型、安装驱动、改全局代理/防火墙、开放公网、清空已有记录或擅自推送。真实API调用或本地模型加载由本人明确确认后进行；模型密钥由本人操作输入，不经GPT转发。

测试顺序：

1. 环境检查：Node、SQLite、照片解码、两版页面构建全部通过。
2. API版与本地版分别独立启动，确认实际地址为Windows的127.0.0.1；原Linux电脑是否开机不应影响页面和本机规则功能。
3. 使用合成物品检查地点留空发布、五餐二楼、未收录地点原文、照片上传保存、寻物多轮更正和排除、订阅、认领核实与交接、留言与回复。个人单机维护者与校内多人账号场景区分；单机版没有Linux上的migui_admin账号。
4. 停止并重启应用，检查本机记录与照片保留；API/本地两版数据不串。
5. 本人授权并准备真实模型后，再分别检查API调用、本地真实推理；断开网络做本地完整闭环，记录是否有外网模型请求、是否仅规则降级、实际模型名称及响应时间。

需要多人账号和管理员留言端到端验证时，先运行既有`tests/location-support.test.mjs`中的隔离合成用例；不要为了测试把本机个人服务开放到公网。

请输出：电脑配置、Node/npm/Ollama版本、每项通过/失败/未测、复现步骤、改动文件、测试日志、未完成项。将合成测试、模拟模型和真实模型结果分开，不将“能打开网页”写成模型验收通过。
