# 觅归针对性QLoRA验证包 dev11

本包由项目编写，使用AI辅助开发。基础模型Qwen3.5-4B、Transformers、PEFT、bitsandbytes属于第三方基础依赖，不代替自研Agent。用途是100步以内的局部微调验证，不是从零预训练或完整参赛作品。

## 数据与采样

训练252个完整合成任务，1116条决策；新增验证84个任务，372条决策。七种场景均通过真实自研执行器的合成金标准状态检查。不是模型完成这些任务，也不是用户真实数据。官方模板3072长度检查全部保留，不截断。独立测试集没有读取，不包含在包内。

针对先前错误类别设计：两至三候选时含糊指代先问；先读取候选上下文再使用真实物品ID；不透明编号防止从“id-1/id-2”猜类型；同色同地点的不同类别干扰物；完整类别条件；成功工具返回后结束；区分拾获与遗失地点并保留人工核验提示。没有复制之前14题作训练答案，但研发已参考验证错误类别，不能把新数据说成无偏独立测试。

训练与验证按完整任务划分，起始/反馈/更正表达分别编写；共享任务结构、有限词汇和部分最终回复，不能证明泛化。全部轨迹由开发者脚本指定再运行实际核心检查，未调用教师模型。程序检查不能替代完整人工审查；无工具失败恢复和真实校园运营样例。原数据和原适配器保留。

--balanced 按“场景+目标动作”桶轮流取样，避免100步抽样过多普通回复而遗漏追问、恢复、订阅。桶内种子42固定随机，记录实际计划的动作、场景和任务数；只使用训练集分桶，不读取验证答案安排训练。过度采样有遗忘风险，不代表增加了独立数据量。未传此参数时保持旧随机抽样行为。

## 服务器运行

独立解压目录 migui-targeted-kit，不覆盖旧migui-training-kit。模型仍是已校验的Qwen3.5-4B；不从10步适配器继续累积，重新从相同基础模型做100步，便于保留对照。

```bash
cd ~/projects/migui-training
.venv/bin/python -m zipfile -e "觅归-针对性训练准备-dev11.zip" .
(cd migui-targeted-kit && sha256sum -c KIT-SHA256SUMS.txt)
.venv/bin/python migui-targeted-kit/train_lora.py --check-data \
  --base-model Qwen3.5-4B --data migui-targeted-kit/data
```

确认1116/372条均保留、七类场景和关键动作齐全、GPU0空闲后：

```bash
CUDA_VISIBLE_DEVICES=0 .venv/bin/python -u migui-targeted-kit/train_lora.py --run \
  --base-model Qwen3.5-4B --data migui-targeted-kit/data \
  --output runs/targeted-100-001 --steps 100 --balanced --max-seconds 1200
```

100步为单样本/步，没有声称完整训练全部样例；20分钟包含模型加载、七条固定验证子集、训练、保存，不含校验分词。超时/错误保留报告，不重用已有输出目录；不自动续跑、增大预算或多卡占用。仅本机权重，不调用外网模型，不覆盖基础模型，不自动部署适配器。

保存成功后还需检查报告和重新加载。新数据提示长度、内容、采样、步数均与旧训练不同，不能将差异单独归因于训练步数；相同旧验证和新增验证上都须对照以检查退步，严格参数匹配与人工语义核对分开。最终须在完整自研Agent执行器上验证状态与权限，再进行导出兼容、真实离线验收。损失下降不等于Agent能力提高。

## v2训练运行适配

本机2080 Ti实际验证后，选择原生支持的BF16，否则选择FP16；PyTorch默认支持检查包含兼容执行，不能直接当原生能力。FP16初始缩放128，发生非有限梯度时让GradScaler跳过更新并降低缩放，同一例最多重试6次，溢出不计成功步数；仍保留有限梯度和裁剪检查。3090仍使用原生BF16。旧准备包保留，v2使用独立目录。

原数据10步FP16本机65.97秒完成；新数据10步本机57.69秒、峰值分配6.31GiB、无溢出重试。都只证明更新和保存，不证明模型效果提高。当前脚本不包含优化器/随机状态检查点，不能无损续训；100步从基础模型重新开始。完整自研Agent模型执行评测是另外的入口，不包含在此训练小包中。
